# ADR-0073：字幕轨由聚合层随详情供给，emby 层只读

## 状态

已采纳。

## 背景

字幕插件的转接处原本落在 **emby 层**（`emby/subtitle-bridge.js`）：emby 层自己问字幕插件要 `tracks`、
自己把轨挂进版本。于是「这条字幕轨从哪来」这件事**只有 emby 链有**，面板自己的聚合搜索页（web）
看不到任何字幕 —— 同一部片，客户端点开有字幕、面板「这条的版本」弹窗没有。

字幕轨的坐标（片名 + 年份 + 季集）在两条链上其实**同源**：emby 链是客户端给元数据坐标、emby 反查后
**注入真名**再交给聚合层搜源；web 链是聚合搜索的编辑框关键字。也就是说，「搜源用的名字」在聚合层
**已经有一份**，把字幕编排放在聚合层不需要新增任何输入。

另一个约束来自契约：**面板侧不为字幕另开缓存**（字幕内容缓存归插件自己），且**为一个播放目标只问一次
`tracks`**、把轨挂到该目标的每个版本上(见另一仓库 `MediaBridge-plugin-devkit/framework/contracts/contract-subtitle.md`)。

## 决定

1. **转接处整体迁到聚合层**：`subtitle-bridge.js` 从 `emby/` 移到 `agg/`；对插件仍只经
   `plugin/host.js` 的 `call()`，对上游仍只有一条入口。emby 层**不再自己问字幕插件**。
2. **字幕随详情供给**：`agg.detail()` 在返回前编排一次字幕 —— 仅当「**至少一个站拿到详情**
   （`sites[].detail` 存在）**且调用方给了 `name`**」时问一次 `tracks`，把 `subtitles`
   挂在整个播放目标上（不分线路）。失败**只降级**（不出字幕、记一行日志），不影响详情本身。
3. **字幕不进线路缓存**：线路那份照旧走详情缓存，字幕**现算** —— 缓存命中时也现问一次。
   面板侧不为字幕另开缓存（沿用契约）。
4. **HTTP 出口剥 `ref`**：`/api/agg/detail` 对外的 `subtitles` 只留 `{lang, format, label?, source?}`，
   `ref`（不透明凭据）**不下发**（先例：搜索出口删 `ranked`）。`source` 是**申报该轨的字幕插件名**
   （由合成处按插件带进来，不是插件自报），供面板「这条的版本」弹窗标来源。emby 层走进程内直调，
   仍拿得到 `ref`，取内容时调 `agg.fetchSubtitle(ref)`。
5. **坐标口径**：`{ name, originalName, year, season, episode }`。emby 链的 `name` = 坐标反查出的
   规范名（`searchTitle || title`）；web 链的 `name` = 那次搜索编辑框里的文字（`wd`）。
   `agg` 自身**从不解析**站点协议，只透传坐标。

## 备选方案

- **字幕留在 emby 层，web 页单独再接一次字幕插件**：面板会出现**两个字幕来源**，各接各的，
  等于把编排复制一份；一旦坐标口径或失败降级改动，两处要同步。否决（违反「一处实现」）。
- **字幕进搜索响应**：搜索是「找有哪些条」，此时还没有「这条用哪个播放目标」的坐标，字幕无从定位；
  且会把搜索扇出放大（每条结果都要问一次）。否决。
- **字幕给面板侧单独开一份缓存**：契约规定缓存归插件，面板另开一份会造成两份口径。否决。
- **HTTP 出口把 `ref` 一并下发**：`ref` 是插件的内部凭据，面板出口没有消费它的场景（取内容走
  `fetchSubtitle` 的进程内路径），下发只是把内部标识暴露给浏览器。否决。

## 后果

- 面板「聚合搜索 · 这条的版本」弹窗与 Emby 客户端**共用同一处字幕来源**，行为一致。
- 对 **Emby 对外契约零变化**（字幕轨形状、内容端点、鉴权、`MediaSourceId` 载荷都不动）；
  变的只是面板内部取数位置与面板自用 API `/api/agg/detail`（新增 `subtitles`、出口剥 `ref`）。
- 扇出：字幕只在**详情**这一步追问一次（每个播放目标一次 `tracks`），不进搜索、不逐条目放大。
