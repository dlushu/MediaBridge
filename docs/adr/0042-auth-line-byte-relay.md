# ADR-0042 `proxy` 线路：面板代持鉴权头中继（字节转发）

- 状态：已采纳
- 相关：[0006](0006-redirect-for-playback.md)（本文是它针对"要鉴权头的线路"的局部例外）、
  [0040](0040-hls-playlist-relay.md)（同一个流端点里的另一档）、
  [0030](0030-play-address-handoff.md)（地址由插件给、面板只落法）

## 背景

流端点（`GET /api/agg/stream`，面给面板之外的播放器）此前只会两件事：非清单 **302**、HLS 清单 **200 中继**（补绝对，见 0040）。两种都建立在同一句假设上：**地址裸用就能播**（契约里 `playVia:'client'`）。

假设不成立时就有一个洞：源插件回的是**必须带一串鉴权头才取得动**的地址（Cookie / `Referer` / 签名头），而外部播放器**带不了那些头**。这条线路：

- 源插件**自己不做代理**（不是所有源都能像猫爪那样自造一个 `/proxy`：那是为"难缠上游"写的，要凭证签名、按坐标取文件）；
- 出口插件**也交不出头**（FW/Rex 宿主能把请求头交给播放器，别的宿主不一定）。

面板于是**只能 302** —— 一个必然播不了的死路，日志里只有一行"该线路要求请求头，302 后客户端带不了"。

## 决定

流端点按契约的 `playVia` 声明**分档落法**，多出第三档"面板代持头中继"：

| `playVia` | 地址 | 面板怎么落 |
|---|---|---|
| `client`（缺省） | 非清单 | **302**（字节全在源与客户端之间跑） |
| `client` | `.m3u8` | **200 清单中继**：取回、相对补绝对、原样回（0040，不改） |
| `proxy` | 非清单 | **字节中继**：带着源给的头去取、原样搬到客户端（搬运方式已由 0045 改为**分块并发**；[0077](0077-relay-small-object-single-connection.md) / [0078](0078-segment-object-single-connection.md) 起：**8MB 以内单连接直搬**，更大的前缀流式 + 分块并发） |
| `proxy` | `.m3u8` | 取回清单后，把**清单里每个地址**改写成面板自己的**签名子地址**；客户端取子地址时由面板带头发给上游 |

配套的三条硬约束：

1. **判据只能是声明，绝不看 `header` 是否非空。** 源顺手给的头可能只是信息性的（实测 missav 给了头、302 照样播）。按事实反推 = 面板替插件纠错 —— 契约明确不这么做（漏标 / 标错由插件自负）。
2. **子地址必须签名**（`core/auth.js` 的 `signStreamPart`，HMAC 用面板自己的 `secret`）。用户名下没有这道签名，这个端点就是**人人可用的开放代理**。签名那一步是无状态的（不认会话、不认 token），但**面板还得凭地址里的 `sid` 去内存里那份 `sid → 鉴权头` 表取头**才能带头取片 —— 所以面板重启后旧子地址失效（410），客户端重取一次清单即可（见"后果"）。
3. **只搬运，不做流量管理。** 不自攒缓冲、不把面板内存变成视频缓存。~~不做分块并发~~ —— **改为**：默认**分块并发**（探总长 → 有界 Range 切块 → 多路在飞 → 按序吐），探不出总长或上游不认 Range 才退回单连接 `pipe`（见 [0045](0045-relay-chunked-concurrent.md)）；**8MB 以内的对象**（HLS 分片这一档）再进一步：不探、不切、不重下，一发有界 Range 单连接边下边发；更大的则把那一发当流式前缀、后面的块并发续上（见 [0077](0077-relay-small-object-single-connection.md) / [0078](0078-segment-object-single-connection.md)）。

另外，**落法内核只留一份**（`modules/agg/stream.js` 的 `planStream` + 清单工具），agg 流端点与 Emby 层共用。**本文只记 agg 端点这一档**：Emby 那条路当时**不改行为**，它按缺省的 `client` 判，只认 `redirect` 与 `playlist` 两档 —— 后来由 [0044](0044-emby-stream-playvia-relay.md) 补上（`playVia` 编进版本 Id + 多一种字节中继响应形态 + `/api/emby/stream` 子地址）。

## 理由

- **这补的是"源插件做不到"那一格，与出口插件的预解析是并存关系、不是替代。** 出口插件能交出头（FW/Rex 宿主就能）时，自己 `POST /api/agg/play` 拿头和地址、直接交给播放器 —— 省面板带宽，是永远更优的路径，**继续保留**。面板中继是它做不到时的兜底能力，代价是吃面板带宽。
- **放在面板而不是逼每个源插件各写一遍代理**：能自造代理的源（猫爪那类）照旧标 `client`，面板一个字节都不经手；做不到的源，能力缺口由面板这一处补上，而不是每个源各写一套。
- **判据放在声明上，是因为面板在这个位置没有别的可靠信息**：`detail` 阶段还没有地址可测，而"头是不是必需"只有源自己知道。
- **改写成面板子地址是 HLS 的硬要求**：清单里给的是分片地址，客户端照着取 —— 那些请求同样带不了头。不改写，清单取回来也播不了。

## 备选

- **按 `header` 非空自动升级成中继**：否决。这是"面板替插件纠错"，且会误伤（信息性的头会让本来 302 就能播的线路白白吃面板带宽）。
- **Emby 层也接这一档**：本次不做（**后由 [0044](0044-emby-stream-playvia-relay.md) 补上**）。Emby 这条路上客户端同样带不了头，理论上该接；但 Emby 的落法是"返回描述符、由路由层写响应"，要接字节转发得改响应落法，且 `playVia` 目前在版本 Id 里没有承载（见 0039 的载荷形状）—— 属于另一件事，别混在一次改动里。
- **让 Emby 去调 `/api/agg/stream` 端点（端点级复用）**：否决。那条路径认的是**外部访问令牌**、且豁免 cookie，Emby 客户端手里只有 `api_key`/Emby token —— 要么把面板公共入口凭证发给每个客户端，要么多一跳、还要让 agg 端点**再取一次**播放地址。Emby 本来就在同进程直调 `agg`（见 0002），复用只能是**函数级**的。
- **照抄猫爪源的代理手段**（分块下载器、首段预热、坐标取文件）：否决。那是为**难缠上游**（网盘 / 站源 API：要凭证签名、不支持 Range、要按坐标拼段）写的；面板中继面对的是**已经 HTTP 化好的地址**，只需要"正确"不需要"聪明"。自己发明缓冲与分块还会带来上面那三条副作用。
- **让面板一律 302、把带头的责任全推给出口插件**：等于把"面板给客户端提供的能力"绑死在某个插件的实现上。能力必须对任何一个出口插件都成立（见 develop.md 的原则）。

## 后果

- **ADR-0006 多一条例外**：`client` 只有在"地址裸用可播"时才成立；`proxy` 线路的媒体字节**确实会经面板**。这是刻意的取舍 —— 播得动优先于省带宽。
- **面板多一份内存态**：`sid → 鉴权头`（TTL 6 小时、上限 256 条，先进先出）。面板重启即失效，客户端重取一次清单即可。
- **子地址是"面板发出去的凭证"**：它的签名随面板 `secret` 变（面板重启不重置密钥，改密码也不重置，见 `core/auth.js`）。运维上要知道：泄漏一条签名子地址 ≈ 泄漏那一份流。
- **日志能看出走了哪一档**：中继每跳打一行（`⇄ 中继 … → 200/206`），结束时打搬运量。分片量大时这几行会很多 —— 这是刻意的，便于判断"到底有没有走中继、搬了多少"。
- **认不出的相对地址不会被改写**（非标准写法），那种清单仍会播不了 —— 与 0040 同一后果。
- 出口插件若给 `proxy` 线路发面板流地址，**必须带上 `playVia=proxy`**（缺省 `client`，不带就仍按 302 走）。
