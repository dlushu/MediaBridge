# ADR-0081 分集列表按实例隐藏未播出的集

- 状态：已采纳
- 相关：[0008](0008-no-fabricated-data.md)（不编数据：这里的"隐藏"是**不还元数据里已存在的**，不是造）、
  问题[#6](https://github.com/dlushu/MediaBridge/issues/6)（两类样本的根因讨论）

## 背景

元数据插件的 season 数据里带**未播出**的集：一部分带**未来** `premiereDate`（issue #6 的「仙逆」
E200 排到一年之后），一部分是**没有日期**的占位条目（同 issue 的「毛雪汪」最后一集，前面所有集
都各有日期、独它没有）。真机 Emby 的分集列表只列磁盘上存在的文件，天然不会出现；本面板是按
元数据整季照列 —— 客户端把未播出集点开是空壳，观感是「坏了一集」。

## 决定

- `getEpisodes` 默认按两条规则过滤：
  ① `premiereDate` 晚于现在 → 不列；
  ② 没有日期、且排在**最后一个有日期的集之后** → 不列（占位）——只在结尾判，中段的无日期条目
  若其后仍有有日期的集则保留；
  整季一集日期都没有时两条规则都无从判断，**原样列出**（没有定位点，无法与「未播出」区分）。
- **开关按实例设置**（实例页「未播集」勾选，`hideUnairedEpisodes`），缺省**开**（与真机一致），
  字段缺席 = 开（老实例升级后直接得到该行为）；关掉即回「元数据给什么列什么」—— 抢先版 /
  泄露版自己想看的用户把开关关掉即可。
- 过滤发生在**分集列表一层**（`getEpisodes`），不改 `getSeasons` / 条目详情 / `NextUp` 的形状：
  季列表的分集计数（`UnplayedItemCount` 等）来自季数据本身，不受影响。

## 理由

- 本面板之所以与真机行为不同，是**数据源形态差异**（整季元数据 vs 磁盘扫描），不是刻意偏离；
  默认向真机对齐，是把两者都能复现的「已知坏观感」放回「与真机无差异」。
- 放在**实例级**而不是全局：一个部署可能同时给两类用户（想干净看剧的 / 想追抢先版的），让部署者
  按客户端分开配。
- 「末尾无日期占位」按**位置**判而不是按 xdays 猜：无日期本身既可能是未播出也可能是数据缺失，
  只有「在一个有日期的集之后」才与"未播出"对得上；整季无日期时猜任何一条都可能与真数据混淆。

## 备选（否决）

- **环境变量全局开关**：对不及格 —— 多实例部署没法分客户端处理，且面板已有实例级配置的先例
  （`allowDownload`），沿用一致机制。
- **在季数据接口（插件层）滤**：每个元数据插件都要各写一遍，且插件侧拿不到"现在的时刻"与统一
  口径；emby 层一处实现，插件不用动。
- **把占位集照列**（只滤未来日期）：「毛雪汪」这类全季有日期、独末集占位的样本依旧翻给用户。

## 后果

- 契约变化写进 [emby-compat](../emby-compat.md)「五」`Shows/{Id}/Episodes` 行与「契约变更记录」；
  真机对照登记在「8」的 8-6；实现见 `service.js` 的 `hideUnairedEpisodes()` 与 `getEpisodes` 里的
  过滤链；实例字段见 `instance.js`（`publicInstance` / `add` / `patch` / `validate`）与实例页
  「未播集」勾选（`public/modules/emby/instances.js`）。
- 默认开 = 对老客户端是**行为变更**（未播出集从列表消失）：已在「契约变更记录」声明；开关关掉
  立即恢复旧行为。
