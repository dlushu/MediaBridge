# ADR-0079 封面地址三形态：中继与图床各归各，判据只认前缀

- 状态：已采纳
- 相关：[0036](0036-image-endpoint-redirect.md)（图片端点一律 302）、[0058](0058-favorite-items.md)（快照只存图片路径）、
  [0042](0042-auth-line-byte-relay.md) / [0077](0077-relay-small-object-single-connection.md) /
  [0078](0078-segment-object-single-connection.md)（流中继那一侧）、[0044](0044-emby-stream-playvia-relay.md)（同一层两端口的分布）

## 背景

1.9.5 引入过一次整库封面刷 501 的回归，链路值得完整记下来 —— 它暴露的不是一个正则写错，
而是**「一个地址、两套解释」**：

1. 出图那一跳（`Items/{Id}/Images/{type}`）把**以 `/` 开头**的地址一律当成"面板自己的中继地址"，
   补上**本跳 origin**：`http://实例:8092/1CIa….jpg`。
2. 而 tmdb 这类**元数据插件给的封面是图床自己的相对路径**（`poster_path`，如 `/1CIa….jpg`），
   本该按该域声明的 `imageBase` 拼成 `https://image.tmdb.org/t/p/w500/1CIa….jpg`。
3. 于是 302 出去的是**面板自己都不提供的地址**（实例端口对根路径回 501），
   而 Emby 客户端（实测 Rex 1.0.1）**只会在自己的 API 前缀 `/api/emby/` 下发请求** ——
   它把那个 Location 改写成 `/api/emby/1CIa….jpg`，同样 501。日志里就是成片的
   `✘ emby 未实现 GET /api/emby/….jpg`；实测那台面板**210/210 条图片 302 全是这种形态**。
4. 同一形状在**五个文件里各判一遍**（`meta-bridge.imageUrlOf`、`home.imageRef`、`service.parseImageTag`、
   `routes.imagesByType`、`stream.signImagePath`），其中**一处**被放宽成 `^/` 就与其它几处分道扬镳。
5. 契约侧本来也不一致：`imageBase` 这个**面板真正在用的域声明字段**在 devkit 契约里**根本没写**，
   而 `contract-home.md` 还把 `poster` 限成"完整 http(s) URL"——插件作者无从知道该给哪种形态。

## 决定

### 一、封面地址只允许三种形态，没有第四种

| 形态 | 插件怎么写 | 面板做什么 | 302 目标 | 谁取字节 |
|---|---|---|---|---|
| **A 图床直链** | 完整 `https://…/x.jpg` | 原样透传 | 第三方绝对地址 | 客户端 |
| **B 面板代取** | `/api/emby/img/{图床host}/{path}`（可选 `mbh` 头） | 补**本跳 origin** + 面板签名 | `http://…/api/emby/img/…?mbm=…` | 面板（带插件申报的 Referer/UA） |
| **C 图床相对路径** | `/x.jpg`（配合域声明的 `imageBase`） | **写入侧**按 `imageBase + size + path` 拼 → 变 A | 第三方绝对地址 | 客户端 |

### 二、三条让两侧"配合得上"的硬律

1. **判据的唯一出处是前缀**（`core/image-url.js` 的 `imageKindOf`）：只有 `IMG_RELAY_PREFIX`
   那一个前缀算中继；**禁止任何"以 `/` 开头即中继"的宽判据**。五个文件全都 import 这一处，
   `signImagePath` / `serveImage` 的 host/path 也**从前缀剥**，不按段数硬猜。
2. **面板让客户端"回来取"的地址，必须落在 `/api/emby/` 前缀下**。理由不是美观：客户端（实测 Rex）
   只在这个前缀下发请求，前缀外的同源路径会被它改写、改写完必然 501。
3. **302 一律是绝对地址；C 必须在写入侧就变成 A**。读侧（tag / 索引）只剩"路径"、`size` 已经丢了，
   在读侧拼就得猜 `size`（`w500`/`w780`/`w300`/`w185` 各用于不同位置），猜错就是 404 或画质错位。

### 三、出图那一跳遇到第三种形态：如实 404，绝不产出死地址

`imagesByType` 只认 A/B；其余形态（图床相对路径、裸文件名）**404 + 一行点名日志**。
客户端对"没图"本来就有兜底（跳过），而"错地址"会被它放大成整片 501。

### 四、旧值不迁移

按"缓存不是数据"的口径：旧 tag / 旧索引里的相对路径不写迁移逻辑 —— 旧 tag 判不过 → 回落索引 →
出图那一跳 404（不出图、也不再刷 501）；客户端下次取条目元数据就是新地址。

## 理由

- **形态是协议的一部分，不该靠字符串猜**：B 与 C 长得都像路径，归属却一个在面板、一个在图床。
  把"是不是那个前缀"作为唯一判据，是把语义写死进一个常量，而不是散进五个正则。
- **写入侧拼、读侧不猜**：这也与 [0058](0058-favorite-items.md) 的"快照只存路径"配套 ——
  路径的归属是**域**（`imageBase` 是插件申报的），拼装只在"域还在手上"的那一步做。
- **拒收优于产出**：面板只提供 `/api/emby/` 前缀下的端点，"前缀外的本机地址"永远是死地址；
  与其 302 一个死地址，不如 404（客户端有兜底、日志有名字）。

## 备选

- **读侧按 `imageBase` 现拼（自愈旧值）**：要猜 `size`，猜错即 404 / 画质错位；且把"域"重新拉进
  出图那一跳（那里只有 `itemId`）。**没选**（也不做迁移）。
- **只把 `imageUrlOf` 那行正则改回去**：治得了这一次，治不了"同一形状五处各判一遍"的病根。**没选**。
- **远端图床一律走面板代取（B）**：字节全过面板，代价与收益不成比例（图床大多裸取得到）。**没选**。

## 后果

- 面板侧：判据与前缀各一处；`home.imageRef` 只收 A/B（首页行没有"域"可查 `imageBase`，C 拼不出来，
  如实丢掉）；`parseImageTag` 只放行 A/B；`imageUrlOf` 把 C 拼成 A。
- 旧 tag / 旧索引里的相对路径 → 404（不再是 501 洪水）；**无迁移**，客户端重取条目即为新地址。
- 契约侧同步（devkit 仓）：`plugin-contract.md` 写进三形态表 + 反例；`contract-metadata.md` 补
  `imageBase` 的语义（图床基地址，**不得**指到面板自己）；`contract-home.md` 的 `poster`/`backdrop`
  允许 B 形态（与面板实现对齐）。
- **留作后续**（本次特意没动，各自单独一步带测试）：
  1. 把"中继端点"的**路由注册 / 端口放行 / 门禁豁免 / 签名种类**收成一张表（`core/endpoints.js`）——
     这次 `img`/`hls` 就是手工在 `server.js`、`core/auth.js`、路由三处各加一遍，容易再漏一处；
     它挨着两端口的门禁，风险等级与本次不同，故不混在一起改。
  2. **图片形态自检**（哨兵）：统计出图那一跳见过的形态分布，出现第三种形态就在「系统自检」里报出来 ——
     需要在"扫索引"与"导出计数"之间先定它落在哪一层。
