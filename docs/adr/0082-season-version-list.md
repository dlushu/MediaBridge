# ADR-0082 季条目提供线路版本列表，剧条目不提供

- 状态：已采纳
- 相关：[service.js](../../server/modules/emby/service.js) · [0022](0022-movie-all-play-items.md) · [0063](0063-version-label-at-aggregate-output.md)

## 背景

Emby 里「剧」（Series）与「季」（Season）是容器（`IsFolder: true`、`CanPlay: false`），
版本列表（`MediaSources`）的语义是"这里有 N 个能直接播的文件"。按这一语义，容器没有单一
可播文件，不应给出版本列表 —— 原实现据此在条目详情里对非可播类型提前返回。

第三方客户端并不都遵守这个分界。观测到的两种相反行为：

- **季条目**：部分客户端把季的 `MediaSources` 当作线路选择入口，该字段缺席时线路选择 UI
  没有数据，用户无法在季这一层换线路。
- **剧条目**：点开剧的正确流程是直接列出分集、在集上选版本。若剧条目也带版本列表，
  客户端会在剧详情之后多弹一层锚到 S1E1 的选择，与"直出分集"的流程冲突。

## 决定

- **季**：查源站并给出 `MediaSources`，版本目标锚到该季第 1 集（季没有"自己这一集"）。
- **剧**：保持提前返回，不给版本列表。
- 判断按 Emby 类型（`Season` 作为例外），不按客户端做分支。

## 理由

同一份响应要同时满足两类客户端。给季版本列表不会破坏"点剧直出分集"的流程 —— 季是分集
列表的父级，客户端只有主动请求季详情时才会拿到这份数据；不给剧版本列表则避免了多余的一层
选择。两边都不需要识别客户端，成本只落在真正请求季详情的少数路径上。

## 备选方案

- **剧与季都给版本列表**：剧详情后多一层锚到 S1E1 的选择，与"直出分集"冲突。
- **都不给**：季入口的线路选择 UI 无数据，第三方客户端在季层无法换线路。
- **按客户端 UA 分支**：需要维护客户端名单，且同一客户端不同版本行为不同，无法稳定判定。

## 后果

- 季详情的响应体积与耗时高于剧详情（多一次聚合查询；命中缓存时为毫秒级）。
- 季条目的版本列表锚到第 1 集，仅作为线路入口；实际播放仍以所选集的 `ref` 为准。
