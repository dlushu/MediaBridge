# ADR-0082 片名归一化：标点、全半角、空格不参与比较

- 状态：已采纳
- 相关：[0003](0003-local-title-scoring.md)（打分判据本身）· [match.js](../../server/modules/agg/match.js) ·
  [emby-compat.md](../emby-compat.md)「五」条目详情 · [develop.md](../develop.md)「挑片判据」

## 背景

同一条目在不同上游的片名写法不同，名字分就掉到分数线下，聚合层判成"不是同一部"，版本列表因此变空：

| 目标名（元数据插件） | 候选名（站源 `vod_name`） | 旧名字分 | 旧结论 |
|---|---|---|---|
| `坠落2：死点` | `坠落２：死点` | `0.889` | 碰巧过线（高出 `0.039`） |
| `坠落２：死点` | `坠落2：死点` | `0.800` | 低于 `0.85`，出局 |
| `THE FIRST SLAM DUNK` | `ＴＨＥ ＦＩＲＳＴ ＳＬＡＭ ＤＵＮＫ` | 硬拒 | "候选名清不出主干" |

注意前两行是**同一对名字、方向互换**：旧实现下分数不对称（`0.889` / `0.800`），
只有一侧能过线 —— 这正是"归一化不彻底"的指纹：全角字符在两侧被处理得不一样。

根因有两条，都在归一化层：

1. `normName()` 只有一张**手写标点字符表**，不做 Unicode 折叠。全角数字 `２`、全角冒号 `：`、
   全角字母、合成字符（`Ⅳ`、`②`）都不在表里，于是"同片不同写法"被当成两个名字。
2. `cleanTitle()` 末尾的字符类写作 `[^\u4e00-\u9fffa-zA-Z0-9]`：
   - 会**删掉全角 `２` 却保留半角 `2`**，两侧形态因此在清洗阶段就分岔（上表分数不对称的来源）；
   - 会**整段删掉假名与谚文**（`\u3040-\u30ff`、`\uac00-\ud7a3` 都不在 `\u4e00-\u9fff` 内），
     日文原名与韩文原名一个字都留不住。实测 `ＳＰＹ×ＦＡＭＩＬＹ スパイファミリー` 清洗后为空。

## 决定

1. **归一化按 Unicode 做，不维护标点表**。`normName()` 三步：
   `normalize('NFKC')` → 去空白 → `[\p{P}\p{S}\p{Z}\p{C}]+` 删除
   （标点、符号与 emoji、分隔符、格式与控制字符）。空格的删除放最前，`新选组镇魂歌 江户青春篇`
   与 `新选组镇魂歌江户青春篇` 因此同名。
2. **`cleanTitle()` 的末步按文字类别筛**：`[^\p{L}\p{N}]+` 删除，字母与数字之外全去。
   假名、谚文、拉丁、汉字一视同仁；emoji / 图标（`🎬`、`🗄`）仍被去掉。
   `normNameForClean()` 同样先做 NFKC（它要保留括号结构，只做"温和"归一）。
3. **目标名按两种形态各比一遍，取分高的那次**（`nameScore` → `titleForms` / `compareTitle`）：
   - 形态 ①：清过噪声的**主干**（与候选名同一把尺子，候选名本来就走 cleanTitle）；
   - 形态 ②：只做归一、保留年份等原文信息的**原名**。
   两种形态都得不到分才算对不上。**相对"只比形态 ①"**，这一条只抬不降：原本因"目标名带了
   候选名没有的信息"而失分的对子被救回（如 `斗破苍穹(2017)` 的目标名主干被剥成年份后只剩
   `斗破苍穹`，候选为 `斗破苍穹年番`）。
   注意它与上面第 1 条性质不同：归一化本身**会**让一类分数下降（旧实现把全角字符删掉造成的
   假同名），见"后果"第一条。
4. **信号提取同样先 NFKC**：`extractSignals()` 对 `vod_name` / `vod_remarks` 先折叠，
   全角写的年份、季号、集数（`（２０２４）`、`第２季`、`更２１１`）才抽得出来。
5. 闸门与权重不动：名字硬拒（无公共主干 / 相似度 `< 0.5`）、分数线默认 `0.85`、
   `0.7 / 0.2 / 0.1` 权重、`vod_exact` 短路，全部保持 ADR-0003 的形态。

## 理由

- 标点、全半角、空格不是片名信息，是**排版习惯**。把它们纳入判据，等于让排版差异决定"能不能播"。
  这类差异的来源可穷举（不同上游的数据清洗、输入法全/半角、翻译组的空格习惯），
  而它们的**共同点**恰好是：都不在"文字类别"里。按类别删是**按规则一次覆盖**，按表删是逐条打补丁。
- 手写表的漏项是可证实的：旧表里有 `～` 却漏 `〜`，有 `"` 却漏 `＂`，有 `@` 却漏 `＠`；
  每漏一个字符就够把同片判成不同片，而 NFKC + 类别一次收口，后续新增特殊字符不必再改代码。
- 两种形态各比一遍是**为了修"目标名侧被洗过头"**：候选名侧必须清洗（站源标题带
  `更新至211集`、`1080P`），目标名侧是片名，清洗的意义只是对齐，清洗后**再加回原文形态**补一遍，
  才不会让 `(2024)` 这类被剥掉的信息单向丢失。
- 两形态相加只抬不降，是这次改动可安全落地的关键：相对"只比形态 ①"，命中集合不会缩小，
  回归面只剩"新增命中是否误收"，这一点用反例语料单独验证（见"后果"）。归一化本身的下调只有一个
  可解释的来源（全角字符不再被删），同样列在"后果"里。

## 备选（否决）

- **继续扩手写标点表**：否决。全角变体是开集（每个 ASCII 标点都有全角对），漏一个就复发；
  且已经出现"同表不同斜杠"的情况，维护成本随数据源增加而增长。
- **只放宽分数线（0.85 → 0.8）以容忍全角差异**：否决。`坠落２：死点` 的 `0.800` 会被救回，
  但 ADR-0003 补遗里的近名不同作品（`S三体` 相似度 `0.857`）也会一起进来，
  等于用"误收更多"换"少漏一个"。归一化错在判据，不在阈值。
- **对目标名也直接 `cleanTitle` 后硬比（单一形态）**：否决。目标名里的年份括号会被剥掉，
  `斗破苍穹(2017)` 与 `斗破苍穹年番` 只能按被削短的主干相似度算（`0.571`），
  而这正是要修的"洗过头"；保留原文再比一遍才救得回，且两种形态都留着，年份信息不丢。
- **引入相似度库（Levenshtein / Jaro-Winkler / fuzzball）**：否决。仓库零第三方依赖，
  且现有分项（LCS + 受控限定词 + 番号）已能逐项给出"为什么是这一条"，
  换库不改变归一化缺陷，只增加依赖与不可解释性。
- **把搜索关键词的变体也发给源站（1 个客户端请求放大成 2 次上游搜索）**：不在本条决定内。
  它解决的是另一个层面（站源自身按串检索命不中），且属请求扇出放大，按
  [AGENTS.md](../../AGENTS.md) 的约定需先与部署者确认倍数与受影响端点，未做。

## 后果

- **抬分侧**（语料比对，旧实现 vs 新实现，28 对含正反例）：7 处变化全部为抬分，
  反例（`流星花园`↔`流星蝴蝶剑`、`名侦探柯南：黑铁的鱼影`↔`万圣节的新娘`、
  `SSIS-001`↔`SSIS-002`、`三体`↔`三体漫画`）分数与结论完全不变。
- **下调侧**（只有一类，必须记明）：旧实现把候选名里的**全角字符直接删掉**（旧的字符类只留
  `\u4e00-\u9fffa-zA-Z0-9`），于是"多出一个全角数字/罗马数字/全角字母/假名/谚文"的候选与目标名
  归一后完全相同，白拿 `1.0`。现在这些字符参与比较，退回真实分数。
  系统扫描（11 部片名 × 17 种后缀 × 两方向，共 374 对）里 185 处变化、其中 87 处下调，全部属这类：
  - 数字/圆圈数字后缀走受控限定词：`庆余年`↔`庆余年２`、`斗破苍穹`↔`斗破苍穹②` 从 `1.0` 到 `0.95`；
  - 全角字母、罗马数字、假名后缀走相似度：`庆余年`↔`庆余年Ⅱ` `1.0` → `0.75`，
    `三体`↔`三体ＡＢＣ` `1.0` → `0.571`，`三体`↔`三体スパイファミリー` `1.0` → 硬拒。
  这不是新引入的不一致，而是**拉齐半角口径**：同一对里的半角写法（`庆余年2`、`庆余年II`）在旧实现
  本来就是这些分数 —— 旧版对全角与半角给两套结果，`坠落２：死点` 的 `0.80` 出局正是同一处不对称的另一面。
  受影响的实际判定只有一处边界：名字分从 `1.0` 掉到 `0.95` 且年份差 ≥ 2 年时，总分从 `0.875` 掉到
  `0.831`（低于分数线）—— 例如目标名 `庆余年`（2019）遇上标注 2024 年的 `庆余年２`：
  旧实现把第二季当第一季，现在不命中，方向是对的（季别该由季集与年份分项管，不该靠名字白送）。
- `同名变体` 的典型收益：`坠落2：死点` / `坠落２：死点` / `坠落2:死点(2024)` / `坠落 2 死点`
  四种写法现在都是 `1.0` 同名，同站多条各自取详情、各贡献版本（仍不去重，与 ADR-0004 一致）。
- `normName()` 还被聚合层的**同名计数**（`service.js` 的 `nameCount` / `sameNameSameSite`）使用，
  统计数字会随之略微合并 —— 只影响诊断计数，不参与筛选。
- 抬分侧的一个具体影响需点名：目标名带年份括号时（`斗破苍穹(2017)`），主干形态只剩 `斗破苍穹`，
  与 `斗破苍穹年番` 这类"主干 + 受控限定词"的候选从 `0.571` 抬到 `0.95`。
  它仍受季集与年份分项约束（候选带 2025 时年份差 8 年、总分 `0.831` < `0.85` 出局），
  且与"目标名不含年份"时的既有行为一致（那条路本来就是 `0.95`）；把年份当身份判据不在本算法范围
  （ADR-0003 已说明源条目没有年份字段）。
- 未覆盖的写法差异（如实记录）：
  - **站源检索词**：面板把元数据名**原样**交给源插件 `search`（`wd`），站源自己的检索能否命中
    不由打分决定。`新选组镇魂歌江户青春篇` ↔ `新选组镇魂歌 江户青春篇` 这一对在打分侧
    一直是 `1.0`（空格本来就被删），若仍聚不到资源，失败点在这个检索层，属上面"扇出"那条待定项。
  - **译名/别名不同**（`坠落2：死点` vs `Dangerous Encounter`）不在归一化范围：那属于作品身份对齐，
    需要外部元数据，与 ADR-0003 否决别名反查的理由一致。
