# ADR-0068 「关于」页内嵌公告：内容放仓库，面板取回后隔离渲染

- 状态：已采纳
- 相关：[notice.js](../../server/modules/panel/notice.js)（取回与缓存） ·
  [settings.js](../../public/modules/panel/settings.js)（`noticeCard`，内嵌渲染） ·
  [core/mirrors.js](../../server/core/mirrors.js)（取源候选，与面板更新、插件库共用） ·
  [0067](0067-mirror-fallback-sources.md)（取源候选与走代理时的安全口径） ·
  [0019](0019-self-update-from-release.md)（代码从 Release 安装，与"内容不必发版"相对）

## 背景

面板「设置 → 关于」页想放一段**会变、且与代码无关**的内容：交流群地址、贡献者名单、临时公告。
若把它写进前端源码，每次改动都要走一遍发版流程（改代码、打 Release、用户更新）；写进设置项则要
在面板里做一个编辑器，且多份部署各自维护、无法"一处更新、全体生效"。

仓库里已经有"从 GitHub 取资源"的基础设施（`core/mirrors.js` 的候选与超时），插件库与面板自身更新
都走它。把这段内容也放进仓库、由面板取回显示，是成本最低的一条路。

## 决定

**公告内容作为仓库里的一份 HTML（根目录 `notice.html`）维护；面板新建端点取回，前端在「关于」页
用隔离的 `iframe` 内嵌显示。**

### 内容与取回

- 内容文件：仓库根目录 `notice.html`，默认取回地址
  `https://raw.githubusercontent.com/<repo>/main/notice.html`（`<repo>` 取 `update.js` 的 `repoInfo`，
  与「关于」页显示的仓库地址同源）。改文件并推送即生效，不涉及发版。
- 取源：**复用 `core/mirrors.js` 的候选**（默认先试公共 gh 代理、失败退官方直连），
  与面板更新、插件库同一份口径。`PANEL_NOTICE_URL` 可覆盖取回地址；**显式给出时不再套镜像前缀**
  （用户指哪打哪），置 `off` / `none` / `-` 关闭这张卡 —— 与 [0067](0067-mirror-fallback-sources.md) 一致。
- 端点：`GET /api/panel/notice` → `{html, url, error?}`。**取不到 / 内容为空都回空串**，
  前端据此把整张卡去掉。结果缓存 5 分钟（失败结果也缓存，免得网络不好时每次开「关于」页都重试）。

### 渲染

- 前端用 `iframe` + `srcdoc` + `sandbox`，**不是 `innerHTML`**：
  - **隔离样式**：内容里的 `<style>` / 选择器不会漏到面板，反之亦然；
  - **不执行脚本**：`sandbox` 里**不给 `allow-scripts`**，脚本与内联事件属性（如 `<img onerror>`）
    都不执行。给 `allow-same-origin` 只为量内容高度、把 frame 撑到刚好；给 `allow-popups*`
    让内容里的链接能开新标签。
- **内容为空 / 取不到 → 整张卡不出现**（连标题也不留空壳）。

## 理由

| 做法 | 优点 | 缺点 |
|---|---|---|
| **仓库放 HTML + 后端取回 + 隔离内嵌**（本决定） | 内容与代码分离，改内容不必发版；样式与脚本都受控 | 多一个外部依赖面（取回通道），内容不可信需隔离 |
| 把公告写进前端源码 | 无外部依赖 | 改一个链接也要发版 |
| 面板里做公告编辑器（存设置） | 无外部依赖、可视化编辑 | 每份部署各自维护，做不到"一处改、全体生效"；还要维护一套富文本/编辑器 |
| 前端直连 `raw.githubusercontent.com` | 少一个后端端点 | 依赖浏览器侧网络与 CORS；国内不稳，且绕开了面板已有的镜像候选 |
| `innerHTML` 直接插入 | 简单、天然继承面板主题 | 会执行内联事件属性（XSS 面）；`<style>` 会全局泄漏，破坏面板样式 |

## 后果

- **内容是不可信的**：走第三方代理时，取回的内容可能与仓库原文不同（[0067](0067-mirror-fallback-sources.md)
  的「校验只防传输损坏」）。因此渲染**按不可信内容对待** —— 不跑脚本、样式隔离。要可信内容，把
  `PANEL_NOTICE_URL` 指到自建镜像，或用 `off` 关掉这张卡。
- **改内容需要仓库的写权限**：公告由仓库维护者更新，面板端不做编辑入口。自建部署想改内容，
  用 `PANEL_NOTICE_URL` 指向自己维护的文件即可，不必改代码。
- **取回有最多 5 分钟延迟**：内容更新不是实时的（缓存所致），不作为"必须立刻生效"的通道。
- **一张卡的分支耦合**：前端 `noticeCard` 依赖后端 `/api/panel/notice` 的 `{html}` 形状；
  这是面板自己的内部契约（写在 [develop.md](../develop.md) 的 API 表），非对外接口。

## 备选方案

- **只在前端直连 raw 地址**：省一个端点，但把取源交给浏览器 —— 国内网络与 CORS 都不可控，
  还丢掉了后端已有的镜像候选与缓存。
- **用 `innerHTML`**：实现更短，但 `<style>` 泄漏与内联事件执行两个问题都真实存在，
  与"内容是别人维护的"这一前提冲突。
- **内容随代码发版**：最省事，但正是本条要解决的问题（改个群链接也要发版）。
