# ADR-0080 首页库行的详情：认 `mbphome_*`、回库条目、查不到回 404

- 状态：已采纳
- 相关：[0055](0055-bare-items-query-returns-views.md)（同一个「客户端把库 Id 当条目用」的错位，先例）、
  [0008](0008-no-fabricated-data.md)（不编数据）

## 背景

`Views` 把启用的首页插件行暴露成**媒体库**（`Type: CollectionFolder`、`IsFolder: true`，
Id = `mbphome_<base64url(pluginId|rowId)>`）。但新客户端（实测 RodelPlayer）点开一行库时是按
**条目**处理的：先请求 `GET /Users/{UserId}/Items/{库Id}` 取它的详情，再按返回的 `ParentId`
列内容。此前 `metaBridge.parseItemId()` 认不出 `mbphome_*`，该端点回 **501**，点下去没有后续
—— 从客户端看是「库列出来了，但打不开」。

## 决定

- 条目详情端点（`GET /Users/{UserId}/Items/{ItemId}`）**认领 `mbphome_*`**，回
  `getViews()` 里**同一份**库条目 DTO（不另造形状、不复算）。
- 判据统一走 `home.parseViewId()`：前缀只在 `home` 定义一次，**不在路由层复制 `'mbphome_'` 字面量**
  （历史上这个前缀从 `catpawhome_` 改过一次，复制出来的那处会静默失配）。
- **查不到回 404**：前缀认得出、但那行已不在启用清单（插件停用 / 行被删）→ 404，与「条目 Id
  认得出但查不到」同口径；**不落 501**。501 的语义是「这个端点没实现」，会让客户端当实现缺失去
  重试 / 上报，而这里是确定没有。
- 前缀**不是** `mbphome_*` 的，行为不变（`{域}_*` 条目 Id → 200/404，其余 → 501）。

## 理由

- 根因是**同一个 Id 在客户端有两种语义**（库 / 条目）。修在端点层（认前缀）比在客户端层靠谱，
  也比让每个库行冒充条目干净。
- 复用 `Views` 的 DTO 构造：客户端点开库后按 `ParentId` 列内容，这层本来就实现
  （`Items?ParentId=`，见 [0055](0055-bare-items-query-returns-views.md)），两条链路天然对得上。
- 错误码要告诉客户端「该不该重试」：501 = 端点缺失，客户端通常不重试也不再报；404 = 资源没了，
  可刷新清单 —— 所以「查不到」用 404。

## 备选（否决）

- **继续回 501**：客户端点开库永远无反应，不可接受。
- **在 `metaBridge` 里给条目 Id 判据加一个 kind**：会污染条目 Id 的判据（`{域}_*` 与 `mbphome_*`
  是两套东西），且路由层已有 `sendResult` / 404 惯例，不必抬高改动面。
- **详情端点对任意 Id 都先试 `Views`**：会把「条目 Id 认不出 → 501」的语义搅浑，也可能给不在
  `Views` 里的伪 Id 造出 200（与 0008 冲突）。

## 后果

- 契约变化写进 [emby-compat](../emby-compat.md)「五」的条目详情与「契约变更记录」；真机对照登记在
  「十」#10 的 10-5（**未复测** —— 真机没有「库行 Id」这个概念，无样本可对）。
- 仅此一个端点认领该前缀；`Images` 等本来就按「认不出的 itemId 走 `IsImageEnabled`」的端点无需改动。
