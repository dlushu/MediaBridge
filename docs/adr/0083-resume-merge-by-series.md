# ADR-0083 继续观看按 SeriesId 合并

- 状态：已采纳
- 相关：[service.js](../../server/modules/emby/service.js) · [0023](0023-playback-progress.md) · [0060](0060-nextup-hidden.md)

## 背景

`GET /Users/{UserId}/Items/Resume` 的协议是**按条目**返回：有进度且未看完的条目一条一行，
每行带 `SeriesId`。把同一 `SeriesId` 的行合并成一张卡片，是客户端的责任，官方客户端会这样做。

主流第三方客户端（Hills / RodelPlayer / CapyPlayer）都不聚合。后果是一部剧每看一集就多一张卡：
同一 `SeriesId` 下 S1E1、S1E195、S1E196 各占一行，「继续观看」被同一部剧刷满，其他剧被挤到
后面。同一部剧的多条记录之间没有时间上的先后意义区分，用户看到的是重复内容。

## 决定

返回前按 `SeriesId`（域 + 条目号，**不含季集**）归组，每组只保留**最近播放**的一条。
电影没有季集，各自独立、不参与合并。为保证去重后仍能填满客户端请求的条数，
先按 `Limit × 4` 取候选行，去重后再截断到 `Limit`。

## 理由

协议层保留逐条目语义不变 —— 返回的仍是 `Episode` 条目，只是同一部剧不再重复出现。
对会聚合的客户端没有行为变化（它本来也只显示一张）；对不聚合的客户端，首页恢复成
"一部剧一张卡"。被合并掉的条目数写进日志，便于确认合并生效与排查。

## 备选方案

- **保持逐条目返回**：不聚合的客户端一剧多卡，首页可用性差。
- **返回 `Series` 类型条目**：会改变条目语义（`UserData` 属于集而不属于剧），续播位置需要
  额外映射，且破坏 `HideFromResume` 的逐条目语义。
- **按 `SeriesId + 季` 归组**：同一部剧跨季仍会出现多张卡，与目标不符。

## 后果

- 同一部剧只能从卡片上续播最近看的那一集；其余集需进入剧页选择。
- 库中同剧多集时，返回条数可能少于客户端 `Limit`。客户端按"少于 `Limit` 即末页"处理，
  这是协议既有行为。
- 若最近播放的那一集元数据取不到，该剧在本次响应中整体缺席（与逐条返回时的表现一致）。
